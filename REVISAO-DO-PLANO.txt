F-01  BLOQUEANTE — A migracao para Firebase Auth, como esta escrita, nao funciona
--------------------------------------------------------------------------------
Onde no plano: PB-03 (Fase 2), secao 3 do Bloco B; Onda 3 / PR-11.

O que o plano diz
  "Login pela aplicacao continua, mas apos validar a palavra-passe faz
  signInWithEmailAndPassword para obter token."

Porque falha [CONFIRMADO no codigo]
  As palavras-passe da equipa estao em PBKDF2-SHA256 calculado pelo proprio
  sistema (securityHelper.ts:90-109), com salt e 120.000 iteracoes proprios.
  O Firebase Authentication NAO aceita este formato nem permite importar hashes
  arbitrarios no plano gratuito (so o Identity Platform pago tem importacao, com
  formatos suportados e nunca PBKDF2 caseiro).
  E nao se pode "fazer signInWithEmailAndPassword" porque o Firebase nao conhece
  a palavra-passe — so conhece o nosso hash.
  Consequencia: a Fase 2 do PB-03 e impossivel. Quem tentar executa-la perde um
  dia e volta ao ponto de partida.

Correccao obrigatoria (escrever assim no plano)
  A Onda 3 passa a ter tres pecas, nesta ordem:
   1. Cloud Function `login` (Admin SDK): recebe username + palavra-passe,
      valida o hash PBKDF2 no servidor (mesmo algoritmo, mesmo salt) e devolve
      um customToken. O cliente faz signInWithCustomToken.
   2. Claims: a funcao grava role/username como custom claims no utilizador
      Firebase correspondente (criado no primeiro login).
   3. So depois: firestore.rules passa a exigir request.auth.token.role, e
      credentials deixa de ser legivel pelo cliente.
  Custo real: precisa de plano Firebase com Cloud Functions (Blaze) e de um
  deploy de functions — nao e so frontend. Isso muda o esforco de "M" para "G"
  e acrescenta um pre-requisito que nao estava no plano (seccao 4, J-06).

Licao para o plano: qualquer accao que diga "manter a autenticacao actual e
acrescentar Firebase Auth" tem de ser reescrita. Nao ha caminho paralelo barato.

F-03  GRAVE — Tirar o fallback de hash pode trancar utilizadores fora
--------------------------------------------------------------------------------
Onde no plano: PB-06 ("remover o fallback sha256 de 32 bits").

O que encontrei [CONFIRMADO]
  securityHelper.ts:101-109: sem WebCrypto, o hash e "iterated sha256 ate 1000
  vezes" com uma funcao sha256 propria (:111-133) cujo ultimo recurso e um hash
  de 32 bits em JavaScript (:126-131), preenchido a 64 caracteres.
  Isto tem DUAS consequencias, e o plano so viu uma:
   (a) o hash de 32 bits nao e SHA-256 — e fraco e colide;
   (b) o resultado do fallback NUNCA e igual ao do caminho WebCrypto (iteracoes
       limitadas a 1000 vs 120.000). Ou seja: um utilizador que defina a
       palavra-passe num ambiente sem WebCrypto cria um hash que so verifica
       nesse mesmo tipo de ambiente. Ja hoje isto e um defeito de login
       cross-browser, e nao estava na auditoria.

Porque o plano falha
  "Remover o fallback" sem detectar hashes criados por ele tranca esses
  utilizadores fora. E o plano nao tem forma de os identificar.

Correccao
  - Antes de remover: script de diagnostico que corre os dois algoritmos contra
    cada hash guardado e lista os que so verificam no fallback.
  - Para esses: marcar mustChangePassword = true (o fluxo ja existe:
    LoginPanel.tsx:232) e obrigar a reposicao no proximo login COM WebCrypto.
  - So depois remover o fallback, e passar a recusar login com mensagem
    "este dispositivo nao suporta login seguro" em vez de aceitar hash fraco.

// --- PR-01: parser de blocos por chaves balanceadas (nao por regex guloso) ---
function blocosDeRegras(texto: string): Map<string, string> {
  const mapa = new Map<string, string>();
  const re = /match\s+\/([a-z_]+)\/\{([a-zA-Z]+)\}\s*\{/g;
  let m: RegExpExecArray | null;
  while ((m = re.exec(texto)) !== null) {
    let i = re.lastIndex;
    let nivel = 1;
    const inicio = i;
    while (i < texto.length && nivel > 0) {
      if (texto[i] === '{') nivel++;
      else if (texto[i] === '}') nivel--;
      i++;
    }
    mapa.set(m[1], texto.slice(inicio, i - 1));
  }
  return mapa;
}
