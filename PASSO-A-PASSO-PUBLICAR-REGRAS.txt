══════════════════════════════════════════════════════════════════════════════
  CAMINHO A — CONSOLA DO FIREBASE (recomendado)
══════════════════════════════════════════════════════════════════════════════

  A1. COLE ESTE ENDEREÇO NO NAVEGADOR (é o atalho que salta os menus):

        https://console.firebase.google.com/project/gen-lang-client-0896153566/firestore/rules

       Se a página não abrir ou der "não encontrado", cole este outro e
       navegue a partir dele (o endereço é o mesmo, sem a parte final):

        https://console.firebase.google.com/project/gen-lang-client-0896153566/firestore

       Truque: se os nomes em português o baralharem, acrescente ?hl=en ao
       endereço para ver a consola em inglês (Rules = Regras, Publish =
       Publicar, Data = Dados).

  A2. ESCOLHA A BASE DE DADOS (o passo que faltava).

       Este projeto tem uma base de dados com nome comprido. A consola abre
       muitas vezes na base "por omissão", que aqui não tem os dados.

       • Procure no topo da página um seletor de base de dados — costuma
         aparecer como um menu com o nome da base, ou a indicação
         "(default)" / "Selecionar base de dados".
       • Escolha:

             ai-studio-remixagroxicomoe-5bee6408-7aeb-4603-9bb5-b56ad6507335

       • Confirmação de que está na base certa: no separador "Dados" tem de
         ver as coleções products, sales, cash_movements, audit_logs. Se vir
         uma base vazia, mudou para a errada.

       Nota: em algumas versões, o seletor de base de dados aparece na lista
       lateral (menu próprio com o ícone de base de dados), antes de se entrar
       no Firestore.

  A3. ABRA O SEPARADOR "REGRAS".

       Depois de a base certa estar escolhida, a barra de separadores tem:

             Dados  |  Regras  |  Índices  |  Utilização
             (Data) |  (Rules) |  (Indexes)|  (Usage)

       "Regras" fica ao lado de "Dados". Se vir "Dados" mas não "Regras",
       quase sempre é porque a base de dados ainda não foi escolhida (A2) ou
       porque a página está a meio de carregar — recarregue com F5.

  A4. GUARDE AS REGRAS ANTIGAS ANTES DE AS TROCAR (1 minuto, evita sobressaltos)

       • No editor, clique dentro do texto e faça Ctrl+A (seleciona tudo),
         depois Ctrl+C (copia).
       • Abra o Notepad / Bloco de notas, cole (Ctrl+V) e grave como
         REGRAS-ANTERIORES.txt no Ambiente de Trabalho.
       • Serve para voltar ao que estava, exatamente, se algo correr mal.

  A5. COLE AS REGRAS NOVAS.

       • Abra, na pasta do sistema, o ficheiro:

             REGRAS-FIRESTORE-PARA-COLAR.txt

       • Nesse ficheiro: Ctrl+A e Ctrl+C. (Tem um cabeçalho de explicação
         dentro de um comentário — pode copiar tudo, o Firestore ignora
         comentários.)
       • No editor da consola: Ctrl+A (seleciona as antigas) e Ctrl+V.
       • Antes de publicar, confirme:
            – a primeira instrução é   rules_version = '2';
            – existe a linha           match /cash_sessions/{docId}
            – a última linha é         }

  A6. PUBLICAR.

       • Botão "Publicar" / "Publish", no canto superior direito do editor.
       • Espera-se a mensagem "Regras publicadas" / "Rules published", com a
         hora.
       • Se der erro de sintaxe: o texto foi colado incompleto (quase sempre
         falta o fim). Repita A5 com atenção ao Ctrl+A.
       • Enquanto não for aceite, as regras antigas continuam a valer. Não há
         risco de ficar a meio.

  A7. PROVAR (não salte).

       No próprio editor de Regras existe o "Simulador de regras"
       ("Rules Playground"), normalmente num botão/painel do lado direito:
          a) products · operação get · SEM autenticação  → DENIED
          b) products · operação get · COM autenticação  → ALLOWED

       No programa:
          c) abrir o sistema → botão do turno → abrir turno com a contagem
             da gaveta → deve abrir sem erro;
          d) fechar o turno com a mesma contagem → diferença 0,00 MT e turno
             seguinte aberto.

       Se (c) ou (d) derem "permission-denied" no F12 → as regras de
       cash_sessions não foram publicadas. Volte a A5.

══════════════════════════════════════════════════════════════════════════════
  CAMINHO C — LINHA DE COMANDOS  (confirmado: suporta bases com nome)
══════════════════════════════════════════════════════════════════════════════

  A documentação oficial confirma que o firebase-tools publica regras em bases
  de dados com nome, desde que o firebase.json as declare — e o nosso declara.

  Na pasta do sistema (onde está o firebase.json):

      npx firebase-tools login
      npx firebase-tools deploy --only firestore:rules --project gen-lang-client-0896153566

  Se quiser publicar apenas para esta base de dados (mais explícito):

      npx firebase-tools deploy --only firestore:ai-studio-remixagroxicomoe-5bee6408-7aeb-4603-9bb5-b56ad6507335 --project gen-lang-client-0896153566

  Tem de terminar com  ✔  firestore: released rules

  Requisitos e avisos:
   • Precisa de Node.js instalado na máquina e de internet.
   • O login abre o navegador para autenticar a conta Google dona do projeto.
   • Nunca publique firestore.rules.legacy-open (é a versão aberta).
   • A publicação leva alguns minutos a chegar a todos os servidores. Se logo
     a seguir der erro, espere 2-3 minutos e repita o teste.


══════════════════════════════════════════════════════════════════════════════
  SE ALGO CORRER MAL — VOLTAR ATRÁS
══════════════════════════════════════════════════════════════════════════════

  Sintoma: o sistema abre mas as listas vêm vazias e o F12 mostra
  "Missing or insufficient permissions".

  Opção 1 (a mais segura): repor o texto que guardou em A4.
     Consola → Firestore → Regras → Ctrl+A → colar o REGRAS-ANTERIORES.txt →
     Publicar.

  Opção 2: usar o histórico da consola.
     No editor de Regras há um ícone de histórico/relógio com as versões
     anteriores → escolher a anterior → Publicar.
     AVISO: em bases de dados com nome, o histórico pode não registar as
     publicações feitas por linha de comandos. Se só vir uma versão ou nenhuma,
     use a Opção 1.

  ATENÇÃO: se as regras que estavam publicadas eram as antigas e abertas
  ("allow read, write: if true"), repor essas reabre a base a qualquer pessoa.
  Nesse caso, é preferível corrigir o problema e publicar as regras novas, em
  vez de ficar com a base aberta.

  Causas mais frequentes de falha:
   1. login "Anónimo" desligado (verifique primeiro, sempre);
   2. texto colado incompleto;
   3. regras publicadas na base "(default)" em vez da base com nome;
   4. regras ainda a propagar (esperar 2-3 minutos).
